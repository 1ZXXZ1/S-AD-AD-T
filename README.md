# Samba AD — Автоматическое развёртывание домена

Скрипт для автоматического развёртывания контроллера домена Samba AD на ALT Linux (Альт Домен).

## Возможности

- Полностью автоматическое развёртывание домена из конфигурационного файла
- Проверка статуса и работоспособности домена (9 проверок)
- Удаление домена с понижением роли DC и очисткой
- Автоматическая синхронизация времени (NTP) — критично для Kerberos
- Автооткат функционального уровня, если он не поддерживается сборкой Samba
- Поддержка DNS-бэкендов: `SAMBA_INTERNAL` и `BIND9_DLZ`
- Флаг `--yes` для автоматического подтверждения (CI/CD, автоматизация)

## Требования

- ALT Linux (p11+)
- Права root
- Статический IP-адрес на сетевом интерфейсе
- Доступ к репозиториям ALT Linux и NTP-серверам

## Быстрый старт

```bash
# 1. Скопировать файлы на сервер
git clone https://github.com/1ZXXZ1/S-AD-AD-T.git

# 2. Отредактировать конфигурацию
nano samba-ad.cfg

# 3. Запустить развёртывание
chmod +x samba-ad.sh
./samba-ad.sh install

# 4. Проверить статус
./samba-ad.sh status

# 5. Удалить домен (если нужно)
./samba-ad.sh delete
```

## Использование

```
./samba-ad.sh <команда> [опции]
```

### Команды

| Команда    | Описание                                         |
|------------|--------------------------------------------------|
| `install`  | Развёртывание домена Samba AD (первый DC)        |
| `status`   | Проверка статуса и работоспособности домена      |
| `delete`   | Удаление домена (понижение роли DC + очистка)    |

### Опции

| Опция           | Описание                                              |
|-----------------|-------------------------------------------------------|
| `--cfg <файл>`  | Путь к конфигурационному .cfg файлу (по умолчанию: `samba-ad.cfg` рядом со скриптом) |
| `-y`, `--yes`   | Пропустить подтверждение (автоматический yes)         |
| `-h`, `--help`  | Показать справку                                      |

### Примеры

```bash
./samba-ad.sh install                        # Развёртывание с конфигом по умолчанию
./samba-ad.sh install --yes                  # Без подтверждения
./samba-ad.sh install --cfg /etc/my.cfg      # С указанием конфига
./samba-ad.sh install --cfg /etc/my.cfg -y   # Всё вместе
./samba-ad.sh status                         # Проверка статуса
./samba-ad.sh delete                         # Удаление домена
./samba-ad.sh delete --yes                   # Удаление без подтверждения
```

## Конфигурационный файл

Файл `samba-ad.cfg` содержит все параметры развёртывания в формате `КЛЮЧ=ЗНАЧЕНИЕ`.

### Параметры

#### Основные параметры домена

| Параметр    | Обязательный | Описание                                                        | Пример              |
|-------------|-------------|-----------------------------------------------------------------|---------------------|
| `REALM`     | Да          | Kerberos-область (верхний регистр)                              | `ALMAZ.LCAO`        |
| `DOMAIN`    | Да          | DNS-имя домена (нижний регистр)                                 | `almaz.local`       |
| `NETBIOS`   | Да          | Имя NetBIOS (до 15 символов, верхний регистр)                  | `ALMAZ`             |
| `HOSTNAME`  | Да          | Полное доменное имя контроллера домена (FQDN)                   | `dc.almaz.local`    |
| `HOST_IP`   | Нет*        | IPv4-адрес контроллера домена                                   | `192.168.104.24`    |
| `ADMIN_PASS`| Да          | Пароль администратора (мин. 7 символов, 3 группы символов)      | `P@$$w0rd`          |

> *\* Если `HOST_IP` не указан, Samba определит IP автоматически.*

#### DNS

| Параметр         | По умолчанию     | Описание                                           |
|------------------|------------------|----------------------------------------------------|
| `DNS_BACKEND`    | `SAMBA_INTERNAL` | DNS-бэкенд: `SAMBA_INTERNAL` или `BIND9_DLZ`      |
| `DNS_FORWARDERS` | `8.8.8.8`        | DNS-форвардеры (через пробел)                      |

#### Сервер

| Параметр          | По умолчанию | Описание                                                                  |
|-------------------|-------------|---------------------------------------------------------------------------|
| `SERVER_ROLE`     | `dc`        | Роль сервера (`dc` — контроллер домена)                                   |
| `FUNCTION_LEVEL`  | `2008_R2`   | Функциональный уровень: `2008_R2` или `2016` (с автооткатом)             |
| `USE_RFC2307`     | `yes`       | Поддержка POSIX-атрибутов в AD (`yes`/`no`)                              |

> **Внимание:** Уровень `2016` поддерживается не всеми сборками Samba. Скрипт автоматически проверяет поддержку и откатывается на `2008_R2`, если уровень не поддерживается.

#### NTP и сеть

| Параметр        | По умолчанию     | Описание                                  |
|-----------------|------------------|-------------------------------------------|
| `NTP_POOL`      | `ru.pool.ntp.org`| Пул NTP-серверов для синхронизации       |
| `NETWORK_IFACE` | `eth0`           | Сетевой интерфейс (например: `enp0s3`)   |

#### Прочее

| Параметр             | По умолчанию          | Описание                         |
|----------------------|-----------------------|----------------------------------|
| `BACKUP_DIR`         | `/var/backups/samba-ad`| Директория для резервных копий  |
| `DEBUG_LEVEL`        | `1`                   | Уровень отладки Samba (0–10)    |

### Пример конфигурации

```cfg
# Основные параметры
REALM=ALMAZ.LCAO
DOMAIN=almaz.local
NETBIOS=ALMAZ
HOSTNAME=dc.almaz.local
HOST_IP=192.168.104.24
ADMIN_PASS='P@$$w0rd'

# DNS
DNS_BACKEND=SAMBA_INTERNAL
DNS_FORWARDERS="8.8.8.8 8.8.4.4"

# Сервер
SERVER_ROLE=dc
FUNCTION_LEVEL=2008_R2
USE_RFC2307=yes

# NTP и сеть
NTP_POOL=ru.pool.ntp.org
NETWORK_IFACE=enp0s3

# Прочее
BACKUP_DIR=/var/backups/samba-ad
DEBUG_LEVEL=1
```

## Что делает `install`

Развёртывание состоит из 11 шагов:

| Шаг | Описание                                                              |
|-----|-----------------------------------------------------------------------|
| 1   | Обновление системы (`apt-get update`)                                 |
| 2   | Установка пакетов (`task-samba-dc`, `chrony`, `krb5-kdc`, `bind-utils`) |
| 3   | Настройка NTP-сервера (chrony) + принудительная синхронизация времени |
| 4   | Установка имени хоста (`hostnamectl`, `/etc/hosts`, `/etc/sysconfig/network`) |
| 5   | Настройка DNS (resolvconf → 127.0.0.1, отключение DNSStubListener)   |
| 6   | Остановка конфликтующих служб (smb, nmb, krb5kdc, slapd, bind)       |
| 7   | Очистка старой конфигурации Samba                                     |
| 8   | Развёртывание домена (`samba-tool domain provision`) + автооткат уровня |
| 9   | Настройка Kerberos (`krb5.conf`) + проверка прав sysvol              |
| 10  | Запуск служб (samba, bind) + ожидание инициализации                   |
| 11  | Проверка работоспособности (вызов `status`)                           |

## Что проверяет `status`

| # | Проверка                                 | Критичность |
|---|------------------------------------------|-------------|
| 1 | Служба `samba` активна                   | Критично    |
| 2 | Служба `bind` активна (если BIND9_DLZ)   | Критично    |
| 3 | Служба `chronyd` активна + смещение часов | Критично   |
| 4 | Информация о домене (`samba-tool domain info`) | Важно |
| 5 | DNS: resolv.conf → 127.0.0.1             | Важно       |
| 6 | DNS: разрешение записей домена (A, SRV)  | Важно       |
| 7 | Kerberos: `krb5.conf` и `default_realm`  | Важно       |
| 8 | smb.conf: наличие и корректность          | Важно       |
| 9 | Общие ресурсы sysvol и netlogon           | Важно       |

> Проверка ресурсов sysvol/netlogon выполняется через авторизованный доступ (`ALMAZ\Administrator`), т.к. анонимный доступ на AD DC запрещён.

## Что делает `delete`

Удаление состоит из 6 шагов:

| Шаг | Описание                                              |
|-----|-------------------------------------------------------|
| 1   | Проверка FSMO-ролей                                   |
| 2   | Понижение роли DC (`samba-tool domain demote`)        |
| 3   | Остановка служб (samba, bind)                         |
| 4   | Удаление файлов Samba (`/var/lib/samba`, `smb.conf`)  |
| 5   | Восстановление DNS-настроек (resolvconf)              |
| 6   | Перевод NTP в режим клиента                           |

> Если это единственный DC в домене — `demote` завершится ошибкой, но скрипт продолжит удаление вручную.

## Важные замечания

### DNS-бэкенд BIND9_DLZ

При выборе `DNS_BACKEND=BIND9_DLZ` скрипт автоматически:

1. Устанавливает пакеты `bind` и `bind-utils`
2. Отключает chroot (`control bind-chroot disabled`)
3. Отключает `KRB5RCACHETYPE` в `/etc/sysconfig/bind`
4. Закомментирует `/etc/bind/local.conf` (предотвращает конфликт зон)
5. Настраивает `/etc/bind/options.conf`:
   - `tkey-gssapi-keytab` — интеграция с Kerberos
   - `minimal-responses yes` — уменьшение объёма ответов
   - `listen-on` — IP-адреса для прослушивания (127.0.0.1 + HOST_IP)
   - `allow-query` — разрешённые подсети (auto: `localnets` + `HOST_IP/24`)
   - `allow-recursion` — рекурсивные подсети
   - `forwarders` — внешние DNS-серверы из `DNS_FORWARDERS`
   - `forward first` — сначала пересылать, затем кешировать
   - `logging` — подавление предупреждений о lame-servers
6. Создаёт override `bind.service` с `LDB_MODULES_DISABLE_DEEPBIND=1` (фикс падения bind на ALT Linux)
7. Подключает плагин BIND_DLZ в `/etc/bind/named.conf` (после provision)

> **Важно:** BIND9_DLZ даёт расширенные возможности (DNSSEC, условная пересылка, кеширование), но требует больше настройки. Для простых сценариев рекомендуется `SAMBA_INTERNAL`.

### Время и Kerberos

Kerberos требует синхронизации часов в пределах **5 минут** между клиентом и сервером. Скрипт автоматически выполняет `chronyc makestep` при установке, но если после перезагрузки время снова сбилось — выполните вручную:

```bash
chronyc makestep
```

### Функциональный уровень

- `2008_R2` — поддерживается всеми сборками Samba (рекомендуется)
- `2016` — требует Samba 4.11+ с поддержкой уровня DC 2016. Скрипт автоматически откатится на `2008_R2`, если уровень не поддерживается

### Пароль администратора

Пароль `ADMIN_PASS` должен соответствовать требованиям сложности:
- Минимум 7 символов
- Минимум 3 из 4 групп: заглавные буквы, строчные буквы, цифры, спецсимволы

### После развёртывания

Рекомендуется перезагрузить сервер после завершения установки:

```bash
reboot
```

### Подключение клиентов Windows

1. Настроить DNS клиента на IP контроллера домена (`192.168.104.24`)
2. Открыть свойства компьютера → Изменить → Ввести домен (`almaz.local`)
3. Ввести учётные данные `ALMAZ\Administrator` и пароль из `ADMIN_PASS`
